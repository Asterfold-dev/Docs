Vigil is a self-hosted monitoring system for the servers you run. A small
outbound-only agent reports host metrics and local checks; the Vigil console
turns them into a fleet view, charts, and alerts.

It is built for a small team that wants a clear answer to “is everything
healthy?” without assembling Prometheus, Grafana, and a query language first.

## What it does

| Area | Details |
| --- | --- |
| **Host metrics** | CPU, memory, swap, load, uptime, processes, network, and mounted disks. |
| **Checks** | HTTP(S) status and body, TCP ports, systemd units, and Docker containers. |
| **Alerts** | Threshold rules, offline detection, failing checks, email and webhook delivery. |
| **Fleet view** | Host status, latest samples, active alerts, and failing checks at a glance. |
| **History** | 1h, 24h, and 7d charts aggregated by the server. |
| **Users & SSO** | Local accounts, roles, sessions, and Aegis OIDC sign-in. |
| **Footprint** | One small Go agent per host, one Node process, one PostgreSQL database. |

## How it fits together

```text
monitored host ── HTTPS push ──▶ Vigil app ──▶ PostgreSQL
   agent             metrics        UI/API       samples
   checks            checks         alerts       state
```

The agent connects outbound over HTTPS. It never opens an inbound port and
never accepts remote commands. Checks are declarative configuration pulled
from the server on each heartbeat.

## Stack

| Layer | Choice |
| --- | --- |
| Framework | [TanStack Start](https://tanstack.com/start) and [React 19](https://react.dev) |
| Data | [Drizzle ORM](https://orm.drizzle.team) and [PostgreSQL](https://www.postgresql.org) |
| Auth | [Better Auth](https://www.better-auth.com) |
| UI | [Tailwind CSS 4](https://tailwindcss.com), Base UI, and Geist |
| Runtime | Node 24 via [srvx](https://srvx.h3.dev) |
| Agent | Go standard library, static Linux binary |

The source lives in [Asterfold-dev/Vigil](https://github.com/Asterfold-dev/Vigil).

## Status

Vigil v0.1 is an early release. Host metrics, enrollment, HTTP and systemd
checks, alert firing and recovery, webhook delivery, offline buffering, and
offline host detection are exercised end to end. Logs, traces, Kubernetes,
Windows agents, public status pages, and agent auto-update are not included
yet.
